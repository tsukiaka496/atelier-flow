## 1. プロジェクト概要

### 1.1 【事実】このアプリは何をするアプリか

- リポジトリ名 / `package.json` の `name`: `atelier-flow`
- UI 文言は日本語。ルートレイアウト `app/layout.tsx` で `lang="ja"`
- 実装されている主領域（ボトムナビ `components/BottomNav.tsx` のリンク先）:
  - ホーム `/` — 週表示と選択日の作業・メモ・シフト・締切
  - 月 `/month` — シフトテンプレートとカレンダーへの配置
  - 案件 `/projects` — 依頼（案件）と作業（タスク）の管理
  - メモ `/memos` — メモの作成・編集・完了
  - 設定 `/settings` — テーマ・ヒント・バックアップ・全削除
- 永続化はブラウザ `localStorage`（およびチュートリアル用 `sessionStorage`）。`package.json` に DB / Auth / API クライアント依存はない
- `app/api/` ディレクトリは存在しない。`"use server"` の使用もない（リポジトリ全体 grep 結果）

### 1.2 【事実】現在実装されている主要機能

| 機能 | 根拠 |
|------|------|
| 案件 CRUD | `app/projects/**`, `lib/projectsRepo.ts`, `lib/storage.ts` の Project/Task |

## 5. 状態管理構造

### 5.1 【事実】分類一覧

#### グローバル（localStorage + 購読）

| ストア | キー | 購読手段 | 書込 API |
|--------|------|----------|----------|
| Projects | `atelier-flow-projects` | `useProjectsRepo` → `subscribeProjectsChanged` | `saveProjectsRepo` / `addProjectRepo` / `updateProjectRepo` |
| Memos | `atelier-flow-memos` | `useMemos` → `subscribeMemosChanged` | `saveMemosRepo` / `addMemoRepo` / `updateMemoRepo` |
| Shifts | `atelier-flow-shifts` | `useShifts` → `subscribeShiftsChanged` | `saveShifts`（`storage.ts`） |
| Shift templates | `atelier-flow-shift-templates` | `useShiftTemplates` → 同上イベント | `saveShiftTemplates` |
| Theme | `atelier-flow-theme` | `useThemeSettings` → `THEME_CHANGE_EVENT` (`atelier-theme-change`) | `saveTheme` |
| Onboarding | `atelier-flow-onboarding` | `useOnboardingSettings` / Context 内 `useSyncExternalStore` | `saveOnboarding` |

#### 画面ローカル prefs（localStorage、repo なし）

| キー | 画面 |
|------|------|
| `atelier-sort` | `/projects` |
| `atelier-show-completed` | `/projects` |
| `atelier-memos-sort` | `/memos` |
| `atelier-show-completed-memos` | `/memos` |

各画面は `useSyncExternalStore` + カスタムイベント（`atelier-flow:projects-list-prefs` / `atelier-flow:memos-list-prefs`）で同一タブ内同期。

#### Context

| Context | 提供内容（要約） |
|---------|------------------|
| `OnboardingContext` | `settings`, `shouldShowHints`, `isTutorialActive`, step/action API（`registerTourAction`, `runTourAction`, `startTutorial`, `skipTutorial`, `completeTutorial` 等） |

#### sessionStorage

| キー | モジュール |
|------|------------|
| `tutorial-session` | `lib/tutorialSession.ts` |
| `tutorial-session-state` | `lib/tutorialSession.ts` |
| `tutorial-created-project-id` | `lib/tutorialCreatedProject.ts` |

#### Local（`useState` のみ・非永続）

各ページ・コンポーネントのフォーム入力・UI 開閉。詳細は [data-model.md](./data-model.md) の状態一覧、および [screens.md](./screens.md)。

### 5.3 【分析】設計上の特徴（事実からの帰結）

- サーバー状態はなく、クライアント完結の「ストレージ購読 + ページローカル UI 状態」構成である
- Projects / Memos は repo 経由でイベントを出し、Shifts / Theme / Onboarding は `storage.ts` が直接イベントを出す、という二系統がある
- Projects / Memos の repo はクロスタブ用に `storage` イベントを購読するが、Shifts の hook は `storage` イベントを購読しない（`useShiftData.ts`）

## 9. 【分析】第三者向けの読み方

1. **ドメインの正本は `lib/storage.ts`**。ルートの `types.ts` は使われない。
2. **画面はほぼすべて Client Component**。サーバーはレイアウト・フォント・テーマ初期化スクリプト・`/memos/new` の redirect 程度。
3. **機能追加の第一候補パス**: 型 → `storage` の get/save →（必要なら repo + イベント）→ hook → page/component。
4. **チュートリアルは横断関心事**で、多数の `data-tour` / `registerTutorialAction` がページに埋め込まれている。UI 変更時は `lib/tutorialSteps.ts` との整合が必要。
